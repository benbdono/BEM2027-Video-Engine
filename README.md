# BEM2027 Video Engine

استوديو عربي لإعداد وإنتاج فيديوهات المراجعة التعليمية الخاصة بمنصة ملخصات BEM2027.

## تشغيل المشروع
1. افتح رابط GitHub Pages أو افتح `index.html` في متصفح حديث.
2. جهّز اسم المشروع والمادة وعنوان الفيديو.
3. من «إدارة المشاهد» أضف المشاهد وعدّل العناوين والنصوص والمدد والانتقالات.
4. يمكن إرفاق صورة خلفية مستقلة بكل مشهد. تُضغط الصورة إلى JPEG قبل حفظها في بيانات المشروع.
5. من «إنتاج الفيديو» أرفق ملفاً صوتياً اختيارياً، ثم اختر «إنشاء الفيديو الآن».
6. بعد انتهاء المعالجة نزّل ملف WebM الناتج.

## حدود معروفة وخطة التطوير
- صيغة الإخراج الحالية WebM وليست MP4. إضافة MP4 تتطلب ترميزاً إضافياً مثل FFmpeg/WebAssembly أو خدمة معالجة، وسيتم اختيار حل مجاني مناسب بعد اختبار الأداء وحجم الملفات.
- الصوت الحالي ملف واحد للمشروع كله؛ لا يوجد بعد توليد صوت آلي أو مزامنة تعليق مستقل لكل مشهد.
- الرسوم الحالية تُرسم داخل Canvas، ويمكن استخدام صورة خلفية لكل مشهد؛ لا يوجد بعد توليد صور بالذكاء الاصطناعي أو تحريك فيديو واقعي.
- خيارات الانتقال المحفوظة في المحرر ستحتاج ربطاً حركياً أكثر تفصيلاً في محرك التصدير.
- التصدير يتم على جهاز المستخدم؛ قد يتطلب الفيديو الطويل ذاكرة ووقتاً كبيرين. استخدم Chrome أو Edge حديثاً، ولا تغلق الصفحة أثناء التصدير.
- لا توجد حالياً خدمة خلفية أو مفاتيح API أو حسابات خارجية مطلوبة.

## الخصوصية
المشروع يعمل من جهة المتصفح. تُحفظ إعدادات المشروع والمشاهد محلياً في LocalStorage، ولا تُرسل إلى خادم BEM2027. ملفات الصوت المختارة لا تُرفع إلى خادم؛ تُستخدم محلياً أثناء التصدير.

## GitHub Pages
من إعدادات المستودع اختر Pages ثم Deploy from a branch، والفرع `main` والمجلد `/(root)`.

## الإصدار التطويري 0.5.0 — مسار تحويل MP4
- إضافة خطوة اختيارية لتحويل ملف WebM الناتج إلى MP4 باستخدام FFmpeg WebAssembly أحادي الخيط.
- تحميل محرك FFmpeg عند طلب التحويل فقط، وليس عند فتح الموقع. حجم ملفات المحرك يقارب 31 MB، لذلك يحتاج أول استخدام إلى اتصال إنترنت ومساحة ذاكرة مناسبة.
- التحويل يجري داخل المتصفح على جهاز المستخدم؛ لا يتم إرسال ملف الفيديو إلى خادم BEM2027.
- تم اختيار المحرك أحادي الخيط لتجنب الاعتماد على ترويسات COOP/COEP التي لا يمكن ضبطها مباشرة في إعداد GitHub Pages القياسي.
- الترميز المستهدف H.264 للفيديو وAAC للصوت داخل حاوية MP4. يجب اختبار التوافق الفعلي في المتصفح المستهدف قبل اعتماد MP4 كمسار إنتاج أساسي.
- مكتبة الواجهة `@ffmpeg/ffmpeg` مرخصة MIT، ومحرك `@ffmpeg/core` المستخدم هنا مرخص GPL-2.0-or-later؛ راجع شروط التوزيع والترخيص قبل إعادة توزيع المنصة تجارياً.
- WebM يبقى متاحاً كمسار احتياطي إذا تعذر تحميل محرك MP4 أو نفدت موارد الجهاز.


## إصلاح تحميل محرك MP4
- يحدد الإصدار الحالي ملف Web Worker المنفصل لحزمة UMD صراحةً عبر `classWorkerURL`، بدلاً من الاعتماد على المسار النسبي الافتراضي الذي قد يفشل عند تحميل المكتبة من CDN على GitHub Pages.
- يجري تحويل ملفات المحرك إلى Blob URLs لتفادي قيود تحميل الموارد عبر النطاقات.
- إذا استمر الفشل، يجب أخذ نص رسالة الحالة من واجهة الاستوديو؛ لا يُعد نجاح الفحص الآلي دليلاً على نجاح التحويل في كل متصفح.


### FFmpeg worker loading fix

The MP4 converter uses the FFmpeg 0.12.10 ESM core and a small same-origin
module worker under `vendor/ffmpeg/`. This avoids the UMD bundle's webpack
lazy-module lookup for a Blob URL, which can fail in browsers hosted on
GitHub Pages. The worker is served with the application; the ESM core and
WASM payload are fetched from jsDelivr and converted to Blob URLs at runtime.


### Native ESM loader update (0.5.3)

The converter imports the official `@ffmpeg/ffmpeg` ESM entry through the
browser's native module loader rather than its UMD/webpack bundle. This avoids
webpack's dynamic-module lookup being applied to runtime Blob URLs. The
FFmpeg class worker remains same-origin under `vendor/ffmpeg/`, while the
single-thread ESM core and WASM binary are loaded from the pinned jsDelivr
release. The renderer script URL is versioned to avoid stale browser caching.
